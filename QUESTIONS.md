# Open questions

Decisions the specs leave open, formulas a tool needed that the spec doesn't give, and anything else for the teacher to confirm. Each entry says what the build did in the meantime, so nothing is blocked.

| # | Where | Question | What the build does for now |
|---|---|---|---|
| Q1 | 00 §1 | The small-screen rule says "show a notice … matching the Gear Train Workbench's current behavior." The Workbench has no on-screen notice today. It only says in help that phones are too small. | A dismissible banner appears below 768 px: "This tool needs a larger screen, at least 1024 px wide, for full use. The readouts still work here." The layout stays usable and readouts stay readable. |
| Q2 | 00 §2 | The Truss Stress Visualizer has only the light theme. The Gear Train Workbench has both light and blueprint. | The palette is copied from the Gear Train Workbench (both themes), with the same token names so the tools look alike. |
| Q3 | 01 §3.3 vs §4 | The default torque output station is "the heaviest load station" in §3.3, but "L/2" in the §4 table. These are the same for the default single load at L/2. | Output defaults to the heaviest load's station, or L/2 when there are no loads. After that it's whatever the student sets. |
| Q4 | 01 §4, 00 §9 | The Sy preset list must ship as placeholders for the teacher to replace. | Presets are "Placeholder steel (400 MPa)", "Placeholder aluminum (250 MPa)", "Placeholder brass (200 MPa)" and "Custom". Every one is flagged "placeholder value in use" in the readout. **Teacher to supply datasheet values.** |
| Q5 | 02 §5.5 | "Accept a drive-request … return a drive-result." Without a server, "return" has to be a file. | The Motor and Drive Matcher loads a `drive-request` JSON (Load menu, or dropped on the page) and offers "Export drive result" as a JSON download. The Workbench and Conveyor Designer will import that file. |
| Q6 | 02 §5.1 | The teacher-editable motor list is "JSON in settings." | The settings dialog has a text area holding the list as JSON, which is validated and saved in local storage. To share the list with a class, the teacher copies the JSON out of the text area and students paste it into theirs. |
| Q7 | 02 mockup | The mockup header shows a Sandbox/Challenge switch, but spec 02 defines no challenges (and neither does spec 01). | Tools 01 and 02 run in sandbox mode only, and predict-first works there. Prediction records use `sandbox-<hash of inputs>` as the problem ID. **Teacher to supply** a challenge list if one is wanted. The shell already supports a mode switch and a `problemId` hook. |
| Q8 | 02 §4 | Voltage, I₀ and I_s default to blank. The shared input fields need a number. | They sit behind the "Show current and efficiency" extension switch, which is off by default, and start at the MD-5 example values (12 V, 0.2 A, 10 A) with the note "The starting values are examples." |
| Q9 | 02 §5.4 | "Add motor to compare" doesn't say whether a compared motor can have several motors in parallel. | Compared motors are single motors (stall torque and no-load speed) sharing the main gearing and load. |
| Q10 | 00 §6 | Neither spec says whether the Report should reveal results that predict-first is hiding. | The report shows hidden values as "hidden until checked", so printing is not a way around predicting. |
